## Browser automation fingerprints: measured, documented, and claimed

*Cutoff: 2026-11-05. Local measurements: Linux x86_64, Playwright 1.64.1, Chromium 153.0.8010.12 (both `chrome-headless-shell` and full build), Google Chrome 155.0.8059.39. No headful browser was available, so headful behavior is from sources, not measured here. Raw results: `/home/abhi/.hermes/cache/scratch/fp-probe/results.json`.*

**Terms used below.** “Shell” = `chrome-headless-shell`, the old headless build Playwright uses by default for `headless: true`. “New headless” = the full Chromium binary launched with `--headless` (Chrome 132+). “Vanilla” = Chrome launched directly, without Playwright or a CDP client. Puppeteer exposes the same split (`headless: true` vs `headless: 'shell'`) per [Chrome’s headless documentation](https://developer.chrome.com/docs/chromium/headless).

### 1. Automation control and CDP

1. **Stock Playwright Chromium reports `navigator.webdriver === true`, but the reliable trigger is the automation transport, not “headless” by itself.** Chromium’s runtime-feature table maps `--enable-automation`, `--headless`, and `--remote-debugging-pipe` to the `AutomationControlled` Blink feature, and maps `--remote-debugging-port=0` specially. In the tested binaries, plain Chrome `--headless` measured `false`; `--enable-automation` measured `true`; `--remote-debugging-port=0` measured `true`; a specific port (`9222`) with a CDP client attached still measured `false`. Playwright 1.64.1 launches with `--remote-debugging-pipe` and no `--enable-automation`, and measured `true`. **Confidence: high. Type: measured + documented.** Sources: [Chromium `runtime_features.cc`, lines 342–344 and 385–399](https://chromium.googlesource.com/chromium/src/+/HEAD/content/child/runtime_features.cc); [Chromium `navigator.cc`, lines 81–88](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/core/frame/navigator.cc); local measurement 2026-11-05.

2. **`--disable-blink-features=AutomationControlled` is the switch that actually clears the flag, and it preserves the native getter.** Measured shell: `navigator.webdriver === false`, descriptor still on `Navigator.prototype`, and `Function.prototype.toString` still returns `function get webdriver() { [native code] }`. Playwright does not add this flag by default; Patchright does. **Confidence: high. Type: measured + documented.** Sources: local measurement; [Patchright README](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright); [Castle, 2025-03-19](https://blog.castle.io/how-to-detect-headless-chrome-bots-instrumented-with-playwright/).

3. **A JavaScript override of `navigator.webdriver` is detectable from the descriptor alone.** Native: own property `false`, getter on `Navigator.prototype`, enumerable `true`, configurable `true`, source `function get webdriver() { [native code] }`. Naive override: own property `true`, enumerable `false`, getter source `()=>false`. **Confidence: high. Type: measured + documented.** Sources: local measurement; [MDN `Function.prototype.toString`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Function/toString).

4. **`Function.prototype.toString` is a general tamper check, but not a standalone Proxy detector.** Native built-ins return `function name() { [native code] }`; a Proxy of a named function returns `function () { [native code] }` with the name dropped while `.name` remains. Bound functions produce the same nameless native string, so toString alone is ambiguous; detectors combine it with `.name`, descriptor shape, and timing. **Confidence: medium. Type: measured (V8/Node 26) + documented.** Source: [MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Function/toString); local V8 measurement.

5. **Playwright’s own default arguments create page-visible side effects.** In 1.64.1 the launch command included `--headless`, `--remote-debugging-pipe`, `--enable-unsafe-swiftshader`, `--disable-extensions`, `--disable-component-update`, `--disable-default-apps`, `--disable-popup-blocking`, `--mute-audio`, `--hide-scrollbars`, and a default 1280×720 viewport, with no `--enable-automation` and no `--disable-blink-features`. Pages cannot read argv directly, but SwiftShader, missing extension APIs, fixed geometry, and muted audio are observable. **Confidence: high for arguments; medium for page-visible mapping. Type: measured.** Source: `DEBUG=pw:browser` launch log, Playwright 1.64.1, 2026-11-05; [Playwright browsers documentation](https://playwright.dev/docs/browsers).

6. **Firefox under Playwright behaved differently: `navigator.webdriver` was `false` in 1.44.1 and was fixed to `true` in 1.45.** This is engine-specific; do not generalize Chromium results to Firefox or Camoufox. **Confidence: high. Type: documented.** Source: [Playwright issue #31039, 2024-05-28](https://github.com/microsoft/playwright/issues/31039).

7. **`Runtime.enable` still leaves a serialization side effect that page JavaScript can observe, but the published 2024 stack-getter PoC did not reproduce on Chrome 153/155.** DataDome’s technique defines a getter on an `Error`’s `stack` property and logs the error; under Playwright 1.64.1 that getter fired zero times even after `Runtime.enable`, `Console.enable`, `Log.enable`, and `Debugger.enable`. Brotector’s alternative — a getter on `Error.prototype.name` — fired 6 times with CDP versus 2 times in a no-CDP control. A Chrome launched with `--remote-debugging-port=9222` and attached over CDP reported `navigator.webdriver === false` but still produced the 6-versus-2 name-getter delta. **Confidence: high for the measured delta; medium for generalization. Type: measured + documented.** Sources: [DataDome, 2024-06-13](https://datadome.co/threat-research/how-new-headless-chrome-the-cdp-signal-are-impacting-bot-detection/) ([archived copy](https://web.archive.org/web/2024/https://datadome.co/threat-research/how-new-headless-chrome-the-cdp-signal-are-impacting-bot-detection/)); [Brotector source](https://raw.githubusercontent.com/ttlns/brotector/master/brotector.js); local measurement.

8. **`Console.enable` is a second documented CDP leak; Patchright disables the Console API to avoid it.** Brotector’s detection treats `Runtime.enable` or `Console.enable` as the trigger. Patchright says it patches both and that console functionality consequently does not work. **Confidence: medium. Type: documented + claimed.** Sources: [Brotector README](https://github.com/ttlns/brotector); [Patchright README](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright).

9. **Playwright binding globals are conditional, not universal.** `window.__playwright__binding__` was absent on a plain page and appeared after `page.exposeFunction`. `window.__pwInitScripts` was absent after `page.addInitScript` in 1.64.1. Castle’s 2025 list of `__playwright__binding__` and `__pwInitScripts` is therefore version- and feature-dependent. **Confidence: medium. Type: measured + documented.** Sources: [Castle, 2025-03-19](https://blog.castle.io/how-to-detect-headless-chrome-bots-instrumented-with-playwright/); local measurement.

10. **CDP-dispatched input is trusted.** `page.click`, `page.keyboard.press`, and `page.mouse.move` produced `isTrusted: true` for pointer, mouse, click, keydown, keypress, and keyup events; `sourceCapabilities` was present on mouse events. `isTrusted` cannot distinguish CDP input from real input. **Confidence: high. Type: measured + documented.** Sources: [MDN `Event.isTrusted`](https://developer.mozilla.org/en-US/docs/Web/API/Event/isTrusted); local measurement.

11. **Headless shell omits the `Accept-Language` HTTP header; new headless and vanilla Chrome send it.** Castle documented the missing header in 2025; measured shell sent none, while new headless and Chrome sent `en-GB,en-US;q=0.9,en;q=0.8`. **Confidence: high. Type: measured + documented.** Sources: [Castle, 2025-03-19](https://blog.castle.io/how-to-detect-headless-chrome-bots-instrumented-with-playwright/); local measurement.

### 2. Headless-mode signatures

12. **`HeadlessChrome` in the user agent is the most robust cheap tell across all current headless modes.** Shell, new headless Chromium, and vanilla Chrome all exposed it; shell used the full build number, new headless and Chrome used the reduced `.0.0.0` form. The 2026 web-scale study independently found Playwright Chromium headless UA carries `HeadlessChrome` and the full build number. Puppeteer exposes the same old/new headless choice. **Confidence: high. Type: measured + documented.** Sources: local measurement; [Castle, 2025-03-19](https://blog.castle.io/how-to-detect-headless-chrome-bots-instrumented-with-playwright/); [Gundelach et al., arXiv:2606.14525, 2026-06-12](https://arxiv.org/abs/2606.14525); [Chrome headless docs](https://developer.chrome.com/docs/chromium/headless).

13. **Client Hints only partly match the UA string.** Shell sent `sec-ch-ua: "HeadlessChrome";v="153", "Not_A Brand";v="8", "Chromium";v="153"`. New headless and branded Chrome sent Chromium/Google Chrome brands without `HeadlessChrome`, while the UA string still said `HeadlessChrome`. A server that checks only `sec-ch-ua` misses new headless; a server that checks only UA catches it. **Confidence: high. Type: measured + documented.** Sources: local measurement; [Castle, 2025-03-19](https://blog.castle.io/how-to-detect-headless-chrome-bots-instrumented-with-playwright/).

14. **`window.chrome` is missing only in the old headless shell; new headless and vanilla Chrome have it.** Shell: `false`. New headless and vanilla Chrome: `true`, with `loadTimes`, `csi`, and `app`. Sannysoft’s “Chrome (New)” row failed for shell and passed for new headless. **Confidence: high. Type: measured + documented.** Sources: local measurement; [Sannysoft bot test](https://bot.sannysoft.com/), 2026-11-05; [Playwright issue #33566, 2024-11-13](https://github.com/microsoft/playwright/issues/33566).

15. **Empty `navigator.plugins` is also shell-only.** Shell: 0 plugins, 0 MIME types, `pdfViewerEnabled: false`. New headless and vanilla Chrome: 5 PDF plugins, 2 MIME types, `pdfViewerEnabled: true`. Playwright’s own headless-shell transition notes list plugins, screenshots, PDF viewer, and extensions as differences. **Confidence: high. Type: measured + documented.** Sources: local measurement; [Playwright issue #33566](https://github.com/microsoft/playwright/issues/33566); [Sannysoft](https://bot.sannysoft.com/).

16. **`outerWidth/outerHeight === 0` is obsolete.** Measured 1280×720 under Playwright and 780×580 under vanilla Chrome headless; the 0×0 value is a 2018 Puppeteer/CDP emulation bug. **Confidence: high. Type: measured + documented.** Sources: local measurement; [Puppeteer issue #2952, 2018-07-25](https://github.com/puppeteer/puppeteer/issues/2952).

17. **The “screen equals viewport” tell is largely a Playwright viewport artifact, not a headless-mode fact.** Playwright’s default 1280×720 viewport produced `screen == inner == outer == 1280×720` with no browser chrome. Vanilla Chrome headless produced `outer 780×580`, `inner ~780×437`, `screen 800×600` — a normal windowed shape. A detector checking `outerHeight - innerHeight <= 1` will flag Playwright, not necessarily headless Chrome. **Confidence: high for measurement; medium as a detector. Type: measured.** Sources: local measurement; [Sannysoft `PHANTOM_WINDOW_HEIGHT`](https://bot.sannysoft.com/).

18. **SwiftShader was the WebGL renderer in all headless runs here.** All modes reported `ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero) (0x0000C0DE)), SwiftShader driver)`. Playwright explicitly passes `--enable-unsafe-swiftshader`; the vanilla Chrome run used `--disable-gpu`. A GPU-enabled headless setup may differ, so this is strong on GPU-less servers and weaker elsewhere. **Confidence: medium-high; high in this environment. Type: measured + documented.** Sources: local measurement; Playwright launch log; [independent gist, 2026-05-21](https://gist.github.com/uinstinct/eb6608a6f42ea797526cc9acc2c38649) (Patchright failed WebGL for the same SwiftShader reason).

19. **The permissions inconsistency is shell-specific.** Shell: `Notification.permission === "denied"` while `navigator.permissions.query({name:"notifications"}).state === "prompt"`. New headless and vanilla Chrome: `"default"` versus `"prompt"`. Playwright issue #23954 reports notifications only work with `headless: false` or `channel: "chromium"`. **Confidence: high. Type: measured + documented.** Sources: local measurement; [Playwright issue #23954, 2023-06-29; comment 2025-05-07](https://github.com/microsoft/playwright/issues/23954).

20. **`chrome.runtime` is not a valid modern headless tell.** Chromium announced that from Chrome 106, `chrome.runtime` is no longer defined unconditionally on ordinary pages unless a connectable extension exists. Measured: absent in shell, new headless, and vanilla Chrome. Detectors still probing it are either checking `window.chrome` by proxy or producing false positives. **Confidence: high. Type: documented + measured.** Sources: [Chromium Extensions announcement, 2022-08-24](https://groups.google.com/a/chromium.org/g/chromium-extensions/c/tCWVZRq77cg/m/KB6-tvCdAgAJ); local measurement.

21. **Hardware and locale values are environment fingerprints, not automation constants.** Measured `hardwareConcurrency: 4`, `deviceMemory: 16`, `platform: Linux x86_64`, languages `["en-GB"]` in shell versus `["en-GB","en-US","en"]` in new headless/vanilla, timezone `Asia/Calcutta` in all. Container/VM values can be rarer; FP-Inconsistent found low core counts helped evade DataDome. **Confidence: medium. Type: measured + documented.** Sources: local measurement; [FP-Inconsistent, arXiv:2406.07647](https://arxiv.org/abs/2406.07647).

### 3. Cross-context and fingerprint consistency

22. **Stock headless is internally consistent across main frame, iframe, and worker.** Iframe `webdriver`, plugins, and `window.chrome` matched the main frame. Worker UA, languages, and `hardwareConcurrency` matched; worker `navigator.webdriver` is `undefined` because `WorkerNavigator` does not expose it. Sannysoft’s `HEADCHR_IFRAME` row failed for shell and passed for new headless. **Confidence: high. Type: measured + documented.** Sources: local measurement; [Sannysoft](https://bot.sannysoft.com/); [CreepJS README](https://github.com/abrahamjuliot/creepjs) (contentWindow test).

23. **A main-frame-only JavaScript patch leaks in iframes.** After overriding `navigator.webdriver` on the top window, a newly created same-origin iframe still returned `true` with the native `Navigator.prototype` getter. Playwright’s `addInitScript` runs in new frames; a one-off `page.evaluate` does not. **Confidence: high. Type: measured + documented.** Sources: local measurement; [Playwright `page.addInitScript`](https://playwright.dev/docs/api/class-page#page-add-init-script).

24. **Canvas was stable, not discriminating, in these headless modes.** The same canvas hash appeared across shell, new headless, Chrome, and iframes in the Sannysoft run; all used SwiftShader. Canvas is an environment fingerprint that can flag a rare environment, but it does not prove automation by itself. **Confidence: medium. Type: measured.** Sources: local Sannysoft results, 2026-11-05; [FP-Inconsistent](https://arxiv.org/abs/2406.07647).

25. **Canvas, audio, WebGL, fonts, and plugins are actively read by anti-bot scripts.** FP-Inconsistent’s table of APIs read by DataDome and BotD includes `navigator.webdriver`, `navigator.plugins`, `navigator.permissions`, `navigator.mimeTypes`, `navigator.languages`, `navigator.hardwareConcurrency`, canvas, and more. The 2026 study found Cloudflare probing eight categories: Canvas, Audio, WebGL, Speech, Fonts, Dimensions, Permissions, and Plugins. **Confidence: high. Type: documented (measurement studies).** Sources: [FP-Inconsistent, Table 5](https://arxiv.org/html/2406.07647v3); [Gundelach et al., arXiv:2606.14525](https://arxiv.org/abs/2606.14525).

26. **Per-load randomization is a self-inflicted temporal inconsistency.** FP-Inconsistent detects temporal inconsistencies across requests from the same cookie; randomization of canvas/audio/fonts makes a device look different on each visit. Consistent-but-rare fingerprints are safer than random ones. **Confidence: medium. Type: documented + inferred.** Sources: [FP-Inconsistent](https://arxiv.org/abs/2406.07647); [CreepJS README](https://github.com/abrahamjuliot/creepjs).

27. **Timezone/IP mismatch is a documented and measured inconsistency.** DataDome lists consistency between IP location, timezone, and languages as a weak signal. FP-Inconsistent found that for one bot service advertising Canadian traffic, IP geolocation matched the advertised region over 90% of the time, but timezone matched only 76.52%. The independent gist also found Patchright configured for `America/New_York` on an India-origin IP. Our local host was internally consistent (`Asia/Calcutta`, `en-GB`), so this is a configuration risk, not an automatic headless artifact. **Confidence: high. Type: documented + measured (third-party).** Sources: [DataDome, 2024-06-13](https://datadome.co/threat-research/how-new-headless-chrome-the-cdp-signal-are-impacting-bot-detection/); [FP-Inconsistent](https://arxiv.org/abs/2406.07647); [gist, 2026-05-21](https://gist.github.com/uinstinct/eb6608a6f42ea797526cc9acc2c38649).

### 4. Vendor claims and independent evidence

28. **Camoufox claims C++-level fingerprint interception and “undetectable through JavaScript inspection,” but its own documentation concedes limits.** It says fingerprint data is “intercepted at the C++ implementation level, making the changes undetectable through JavaScript inspection”; it also says Playwright’s page agent is sandboxed in Juggler and that “it is impossible for a page to detect the presence of Playwright through Javascript inspection.” But the same docs say Camoufox “is not immune to inconsistencies in fingerprint rotation,” “doesn’t always succeed” at consistent spoofing, and its 2026 status note says performance has declined due to the base Firefox version and newly discovered inconsistencies. It also explicitly says it cannot spoof Chromium/V8 behavior. **Confidence: high that these are the claims; medium that they hold broadly. Type: claimed/documented.** Sources: [Camoufox fingerprint docs](https://camoufox.com/fingerprint/); [Camoufox stealth docs](https://camoufox.com/stealth/).

29. **Camoufox’s independent evidence is mixed.** The 2026-05-21 gist scored Camoufox 13/20: it passed BrowserScan, WebGL, canvas, TLS, CDP, and WebRTC, but failed Sannysoft (`window.chrome` absent on Firefox), AudioContext, fonts, timezone/IP, behavioral scrolling, and CreepJS. Issue #995 (2026-11-03) reports hCaptcha detects Camoufox “pretty much 100% of the time” after switching to fpgen; issue #406 (2025-10-22) reports Discord/hCaptcha detecting it every time. Issue #627’s WebRTC-leak report was retracted by its author because the proxy did not carry UDP — a useful warning that environment confounds stealth tests. **Confidence: medium. Type: third-party measured/user reports.** Sources: [gist](https://gist.github.com/uinstinct/eb6608a6f42ea797526cc9acc2c38649); [Camoufox #995](https://github.com/daijro/camoufox/issues/995); [Camoufox #406](https://github.com/daijro/camoufox/issues/406); [Camoufox #627](https://github.com/daijro/camoufox/issues/627).

30. **Patchright claims to be a patched, “undetectable” Playwright, with an explicit pass list.** The README says “With the right setup, Patchright currently is considered undetectable” and lists Brotector (with CDP-Patches), Cloudflare, Kasada, Akamai, Shape/F5, Bet365, DataDome, Fingerprint.com, CreepJS, Sannysoft, Incolumitas, IPHey, Browserscan, and Pixelscan. It patches `Runtime.enable` by using isolated execution contexts, disables the Console API to patch `Console.enable`, adds `--disable-blink-features=AutomationControlled`, removes `--enable-automation` and several other flags, and supports closed shadow roots. It also says it only patches Chromium, that its init scripts can be detected by timing attacks, and that console functionality will not work. **Confidence: high that these are the claims; medium that the pass list generalizes. Type: claimed.** Source: [Patchright README, fetched 2026-11-05](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright).

31. **Patchright’s claims are contradicted in part by independent reports.** Issue #96 (2025-06-14) reports Kasada-protected Hyatt returning 429s with Patchright 1.52.5; the maintainer could not reproduce it and closed the issue as invalid/wontfix, arguing the block was fingerprint/behavior scoring rather than Patchright. Browser-use issue #1582 (2025-05-05) reports Cloudflare blocking after a Patchright update; browser-use reverted Patchright as the default after 0.1.46. The 2026 gist scored Patchright 18/20 but failed WebGL/SwiftShader and timezone/IP. **Confidence: medium. Type: third-party measured/user reports.** Sources: [Patchright #96](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright/issues/96); [browser-use #1582](https://github.com/browser-use/browser-use/issues/1582); [gist](https://gist.github.com/uinstinct/eb6608a6f42ea797526cc9acc2c38649).

32. **Neither stealth stack fixes the environment layer.** The independent gist’s failures for both Patchright and Camoufox were dominated by GPU (SwiftShader), fonts, timezone/IP, and behavior, not by a missing JavaScript patch. Patchright’s README itself tells users to set timezone and locale to match the proxy and warns that WebRTC can expose the real IP. **Confidence: medium. Type: third-party measured + vendor guidance.** Sources: [gist](https://gist.github.com/uinstinct/eb6608a6f42ea797526cc9acc2c38649); [Patchright README](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright); [Camoufox stealth docs](https://camoufox.com/stealth/).

33. **FP-Inconsistent quantifies both evasion and inconsistency detection.** The study collected 507,080 requests from 20 bot services; average evasion was 52.93% against DataDome and 44.56% against BotD. Its inconsistency rules reduced evasion by 44.95–48.11% while maintaining a 96.84% true-negative rate on real users. **Confidence: high (large-scale preprint). Type: documented.** Source: [FP-Inconsistent, arXiv:2406.07647, submitted 2024-06-11](https://arxiv.org/abs/2406.07647).

34. **The 2026 web-scale measurement shows headers dominate headless blocking, but JavaScript probing is widespread.** Across 10,000 sites and 40,000 visits, Chromium headless had a 15% soft-block rate versus 7% for other configurations. Header spoofing alone removed 75% of Chromium-headless-only blocks, yet 46% of sites checked JavaScript properties present only in automated browsers. Cloudflare blocked 37% and Akamai 26% in the headless condition. **Confidence: high (large-scale preprint). Type: documented.** Source: [Gundelach et al., arXiv:2606.14525, submitted 2026-06-12](https://arxiv.org/abs/2606.14525).

35. **DataDome’s own position is that new headless is close to headful; after UA and `navigator.webdriver` fixes, CDP detection is the generic remaining signal, and detection should be multi-layered.** It explicitly recommends behavior, IP reputation, and IP/timezone/language consistency alongside fingerprinting. **Confidence: high as a statement of vendor research; medium as an independent truth. Type: documented (vendor research).** Source: [DataDome, 2024-06-13](https://datadome.co/threat-research/how-new-headless-chrome-the-cdp-signal-are-impacting-bot-detection/).

36. **FingerprintJS and CreepJS illustrate the difference between broad signal collection and a pass/fail oracle.** FingerprintJS says its bot detection analyzes “hundreds of browser attributes and network signals” and explicitly detects Playwright, Selenium, Puppeteer, and antidetect browsers, but publishes no signal list or weights. CreepJS is a tamper/lie detector and fingerprint test suite (contentWindow, CSS, JS runtime, canvas, WebGL, fonts, voices, screen, timezone); its scores are heuristic and should not be treated as a guarantee. **Confidence: medium. Type: documented.** Sources: [FingerprintJS bot detection docs](https://docs.fingerprint.com/docs/bot-detection/overview); [CreepJS README](https://github.com/abrahamjuliot/creepjs).

### What remains uncertain

- **Headful ground truth is missing.** No headful browser was available; `window.chrome`, `navigator.plugins`, geometry, fonts, and GPU behavior on a real desktop were not measured. Vanilla Chrome headless is a partial control, not a headful control.
- **The `--headless` versus `navigator.webdriver` discrepancy is unresolved.** Chromium HEAD source maps `--headless` to `AutomationControlled`, but Chrome 155 and Chromium 156 binaries measured `false` for plain `--headless`. The reason may be version drift, switch propagation, or build differences.
- **`Runtime.enable` detection is version-sensitive.** The 2024 stack-getter PoC failed on Chrome 153/155, while the `Error.prototype.name` variant still showed a 6-versus-2 delta. It is unclear whether the name variant will survive future V8/Chrome changes, or whether anti-bot vendors use other serialization side effects.
- **Exact anti-bot weights and thresholds are proprietary.** Public test pages and vendor blog posts show techniques, not production scoring. A stack that passes Sannysoft/CreepJS can still fail Cloudflare, Akamai, DataDome, or Kasada.
- **Camoufox and Patchright lack a large-scale independent audit.** The main independent comparison is a single 2026-05-21 gist with agent-driven tests and one run per browser. Vendor issues are user reports with disputed causes.
- **Proxy/IP/timezone/locale matching was not tested.** The local host was internally consistent; a real deployment with a proxy may not be.
- **Behavioral biometrics were not tested beyond `isTrusted`.** Mouse trajectories, typing cadence, scroll patterns, and session-level scoring (the Kasada report) are outside this measurement.
- **GPU-enabled headless may remove SwiftShader and geometry tells.** The SwiftShader result is strong on this GPU-less Linux host and in the independent gist, but not universal.
- **Audio and font fingerprints were not measured locally.** Their treatment here rests on vendor/third-party tests and the FP-Inconsistent API list.
- **`chrome.runtime` on headful pages with connectable extensions was not measured.** Chrome 106’s change makes it undefined on ordinary pages, but extensions can change that.
- **Longevity is unknown.** A stack may pass first load and fail after tens or hundreds of requests; Patchright issue #96 describes exactly that pattern.

### Bottom line for the plugin

- **Stock Playwright headless shell is detectable by default.** UA/CH, `navigator.webdriver`, missing `window.chrome`/plugins, permissions mismatch, missing `Accept-Language`, SwiftShader, and CDP side effects are all present. Do not spend a browser stage on a hostile target without fixing these.
- **New headless full Chrome is cleaner but not clean.** It has `window.chrome`, PDF plugins, consistent permissions, and normal header behavior, but still leaks `HeadlessChrome` in the UA, gets `navigator.webdriver === true` from Playwright’s `--remote-debugging-pipe`, uses SwiftShader in GPU-less setups, and remains detectable through `Runtime.enable` side effects. Connecting over CDP to a specific debugging port can make `navigator.webdriver` false, but it did not hide the CDP serialization signal.
- **Camoufox and Patchright reduce JavaScript/CDP tells, not environment tells.** Independent tests show GPU, fonts, timezone/IP, and behavior dominating failures. Use them only with a residential IP, matching timezone/locale, and a real GPU/headful setup where possible.
- **Match the stage to the gate.** If the target is header-gated, clean headers may be enough; the 2026 study attributes 75% of headless-only blocks to headers. If it probes JavaScript, expect fingerprint checks; 46% of surveyed sites did. If it sits behind Cloudflare, Akamai, DataDome, or Kasada, assume multi-layer detection and plan a fallback rather than betting the run on a browser stage.
